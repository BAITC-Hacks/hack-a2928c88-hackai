# Kickoff — первые 30–45 минут (любой агент)

Вход: `docs/CASE.md` (дословный кейс организаторов), `docs/TRACK.md`, `docs/IDEA.md` (черновик из шаблона трека).

1. Прочитай кейс. Выпиши в `docs/IDEA.md` → «Кейс»: пользователь, вход, ожидаемый выход, критерии кейса (если заданы — они важнее общей шкалы, п. 7.3), предоставленные данные/API.
2. Сверь черновую гипотезу из `docs/IDEA.md` с кейсом. Если не совпадает — переформулируй, сохранив паттерн «агент проверяет/собирает с доказательствами, человек подтверждает». Запиши решение в «Decisions».
3. Заполни «MVP scope»: ОДИН основной сценарий end-to-end, 3–5 шагов. Всё остальное — в «Later».
4. Заполни «Проверка»: 5–15 примеров входа с ожидаемым результатом (источник и права на данные), с чем сравниваемся (обычный запрос к модели / ручной процесс).
5. Адаптируй код, не меняя архитектуру:
   - `app/schemas.py` — поля Extraction/Finding под домен;
   - `app/agent.py` — PROMPT_EXTRACT, PROMPT_REVIEW;
   - `app/rules.py` — REQUIRED_KEYS и 2–4 детерминированных правила из кейса;
   - `app/static/index.html` — заголовок и подзаголовок (кто пользователь, что делает);
   - `data/samples/` — 2–3 входа; `eval/cases/` — 3–5 размеченных кейсов.
6. `python -m pytest -q` зелёный → первый деплой (Render/Railway/что дадут организаторы) → URL в README.
7. Чекпоинт часа 1: `scripts/checkpoint.* 1 "каркас под кейс + первый деплой"`.

Не начинай вторую фичу, пока основной сценарий не открывается по публичной ссылке.
