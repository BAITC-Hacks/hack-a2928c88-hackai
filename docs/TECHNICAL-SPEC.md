# ТЗ для студенческих разработчиков

Добавлено по прямому запросу заказчика 23.09.2026. Это необязательный этап после заполнения и подтверждения карточки.

## Сценарий

1. Бизнес сохраняет и подтверждает заполненные поля карточки.
2. Включает «Составить техническое задание для студентов». По умолчанию переключатель выключен: прежняя публикация без ТЗ работает.
3. Нажимает «Сформировать ТЗ с AI». Источник — сохранённые поля заказчика: потребность, контекст, пользователи, данные, ограничения, ожидаемый результат, критерии успеха и формат работы.
4. Видит и редактирует цель, требования, технический подход, критерии приёмки, этапы, риски и открытые вопросы. Дополнительные идеи отделены от базовых разделов. Ни одна не выбрана автоматически; можно выбрать несколько или ни одной, отредактировать описание, пользу, реализацию и проверку результата.
5. Просматривает выбранное ТЗ, сохраняет и утверждает. PDF черновика доступен бизнесу с явной меткой. Затем публикует карточку.
6. Студенты видят утверждённый опубликованный документ в карточке каталога и скачивают PDF. Отклонённые идеи и рабочий черновик не включаются в публичный снимок.

Правки ТЗ снимают утверждение. Изменение исходных полей требует повторной генерации и утверждения. До повторной публикации студентам доступна прежняя опубликованная версия. Выключение переключателя убирает ТЗ из каталога только после новой публикации. Подтверждение полей карточки и её рейтинг не зависят от ТЗ.

## API и хранение

Под `/api/cards/{id}/specification`: `GET /draft`, `PATCH /settings` с `{enabled}`, `POST /generate`, `PUT /draft` с `{content, selected_idea_ids}`, `POST /approve`, `GET /draft.pdf`. Демо-заголовок `X-Demo-Role: business`; изменения требуют `If-Match`. PDF редактора проверяет `If-Match`, если заголовок передан. Устаревшая версия — 409, отсутствующая — 428.

Публичные `GET /api/cards/{id}/specification` и `GET /api/cards/{id}/specification.pdf` читают только опубликованный снимок, до публикации — 404. SQLite хранит черновик в JSON записи карточки; прежние записи без этого поля читаются с выключенной функцией. Общая ревизия предотвращает перезапись конкурентных правок; ожидание AI не держит транзакцию SQLite.

## AI, PDF и запуск

`MOCK=0`: OpenAI Responses + Structured Outputs (`OPENAI_MODEL`, по умолчанию `gpt-4.1-mini`), затем NVIDIA при настроенном ключе. `SPEC_TIMEOUT_SECONDS=90` — отдельный тайм-аут подробного ТЗ для каждого провайдера. Общий лимит вызовов разделяется с извлечением и проверкой карточки. Логи содержат метаданные без текста и ключей.

При `MOCK=1` или разрешённом fallback используется явно подписанный шаблон. При `FALLBACK_TO_MOCK=0` сбой возвращает 503 и сохраняет прежний черновик. Внешнему AI передаются поля карточки. AI не утверждает документ и не принимает решения о командах; предложения проверяет заказчик.

PDF: ReportLab, кириллица, номера страниц, исходные сведения и только выбранные идеи. Docker устанавливает `fonts-dejavu-core`. На Windows используется Arial; для другого окружения можно указать путь `SPEC_PDF_FONT` к TTF с кириллицей. `pip install -r requirements-dev.txt` устанавливает зависимости приложения и тестов.

## Проверки и границы

- 74 pytest после интеграции с main: публикация без ТЗ, утверждение, выбранные идеи, изменение источника, конфликты версий, ошибка AI, длинный PDF, кириллица, сохранность проверки карточки.
- Локальный браузер: заполнение → подтверждение → переключатель → генерация mock → правка → выбор одной идеи → предпросмотр → утверждение → публикация → студенческий документ. Двухстраничный PDF визуально проверен.
- Контракт SDK проверен тестовым клиентом. Реальный вызов AI именно для ТЗ и размещение этой функции на Render пока не проверены. Проверки других AI-функций не являются проверкой этого сценария.
- Демо-роли открыты, без аутентификации и изоляции компаний. Отсутствие черновика в публичном снимке не заменяет защиту доступа: любой может переключиться в роль бизнеса. Использовать учебные данные.
- PDF строится по запросу; документ включён в снимок каталога. Кэш PDF и отдельная загрузка больших документов — дальнейшая оптимизация. Лимиты: до 6 идей, 8000 символов на раздел, до 65000 символов JSON ТЗ.
- Независимое ревью Claude через `scripts/agents.py ask` не обнаружило блокеров публикации/версий; по замечаниям добавлены отдельный тайм-аут, метаданные логов, подсказки пустых разделов и проверка версии PDF. Живые провайдеры остаются непроверенными для ТЗ.
