### 2. Место и следующее полезное действие — 20–30 минут после контракта

В карточке списка показать «Место №… из … в общем каталоге» только при наличии серверных данных. Это глобальное место, а не индекс на странице или в отфильтрованном списке.

В деталях — блок «Как бизнес может улучшить задачу» с максимум тремя действиями:

> Опишите доступные материалы → заполните и подтвердите поле → +20 баллов.
> При выполнении действия и повторной публикации: 50 → 70; предполагаемое место №… .

- Текст действия, дельту, текущий и прогнозный балл, место брать с сервера. Ничего не считать из длины текста и не обращаться к AI из браузера.
- Каждое действие — отдельный сценарий от текущей карточки, не суммировать прогнозы нескольких действий.
- Подпись: «Предпросмотр по текущему состоянию каталога. Место изменится после подтверждения и публикации».
- Если карточка синтетическая — сохранить метку; пояснить, что общий каталог содержит учебные примеры.
- Нет данных о позиции — не показывать вымышленное место. Нет действий — «Все поля рейтинга заполнены и подтверждены»; не писать «успех гарантирован».

### 3. Замечания стресс-теста — 15–25 минут после контракта

Под рейтингом в деталях показать отдельный блок «Что стоит уточнить до старта»:

- Максимум три замечания: название поля, цитата, объяснение, вопрос бизнесу.
- Маркировка «AI-предположение — требует проверки человеком» для модельных замечаний; «Проверка правилом» для детерминированных.
- `mock` явно обозначать как демонстрационную проверку. Не называть её реальным AI-анализом.
- Отсутствующая проверка: «Проверка ещё не выполнена».
- Устаревшая версия: «Карточка изменилась — результаты проверки устарели». Старые замечания не выдавать за актуальные.
- Пустой список после успешной проверки: «Проверка не выявила замечаний; это не гарантия реализуемости».
- Не менять рейтинг, сортировку, доступность отклика, решения или баллы этапов по замечаниям.

## Новый контракт — планируется, сейчас в API отсутствует

Codex добавит необязательное `catalog_insights` в опубликованный `CardView`, возвращаемый существующим `api.listCards(filters)`. Новые HTTP-запросы разработчику 2 не нужны. Существующие поля CardView и методы откликов остаются прежними.

```js
card.catalog_insights = {
  revision: 3,              // версия опубликованной карточки
  as_of: 'ISO-8601',        // момент расчёта позиции
  rank: 125,               // иллюстрация структуры, не реальная позиция
  total: 413,
  actions: [{
    field: 'data',
    label: 'Опишите доступные материалы',
    instruction: 'Заполните поле и подтвердите его',
    delta: 20,
    score_after: 70,
    rank_after: 110         // отдельный условный сценарий действия
  }],
  review: {
    status: 'complete',     // not_run | complete | stale | unavailable
    revision: 3,           // версия, на которой выполнен анализ
    mode: 'live',          // live | mock; null если проверки не было
    provider: 'openai',    // строка или null
    issues: [{
      field: 'data',
      kind: 'ai',          // ai | rule
      quote: 'Данные обсудим позже',
      message: 'Из описания неясно, что будет доступно команде.',
      question: 'Какие материалы вы сможете предоставить?'
    }]
  }
};
```

Числа и текст выше — только пример формата. **Не встраивать этот объект в рабочий каталог.** Пока backend не готов, можно проверять отображение через отдельный локальный тестовый адаптер, явно помеченный как фикстура; не коммитить его в продуктовые модули.

Если `catalog_insights` отсутствует или его `revision` отличается от `card.revision`, скрыть прогнозы, показать нейтральную недоступность проверки, оставить весь основной сценарий рабочим. При несовпадении `review.revision` показывать устаревание независимо от текста замечаний. Не вызывать `api.getCard` ради анализа: он возвращает рабочую версию бизнеса, которая может отличаться от опубликованной.

При интеграции Codex передаёт фактический пример API. До этого готовность блоков 2–3 только визуальная, не сквозная.

## Приёмка

1. На наборе 413 карточек: 20 на странице, поиск и два фильтра совместимы, сброс возвращает полный набор; порядок совпадает с API.

3. Показаны раздельно реальные баллы и условный результат действия. Из просмотра прогноза не возникает PATCH/confirm/publish.
4. Все состояния review показаны; ошибка AI не ломает каталог. Неподтверждённые замечания не называются фактами.
5. Строки AI и пользовательский текст выводятся через `textContent`, не `innerHTML`. Ссылки только HTTP(S).
6. Задача <40 принимает отклик. Бизнес вручную выбирает несколько команд или отклоняет все. Повтор этапа не начисляет ещё +10.
7. Ошибка отправки не стирает идею, план и срок. Двойной клик не отправляет дубликаты.
8. Нет ошибок в консоли; отсутствующие новые поля API не ломают старую версию приложения.

Проверить локально с `MOCK=1` и настоящим backend: `.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000`. Данные учебные. Изменения ветки не появляются на Render автоматически.
