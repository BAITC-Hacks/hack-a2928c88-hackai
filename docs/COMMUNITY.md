# Вопросы, опросник и рекомендательные письма

Расширение Sana Hub по ТЗ «Вопросы-ответы и рекомендательное письмо»: студент задаёт публичный вопрос в опубликованной карточке, заказчик отвечает и при необходимости переносит ответ в рабочую карточку. После проекта заказчик заполняет опросник; подтверждённые участники получают личные PDF-копии одного командного письма с QR-проверкой.

Это проверяемый учебный сценарий с серверными сессиями и проверками прав. Переключатель демо-пользователей открыт намеренно. Здесь нет производственной аутентификации, проверки личности подписанта или электронной подписи. Новые функции требуют отдельного обновления публичного сервиса; наличие кода в ветке не означает, что они уже установлены на Render.

## Запуск без внешних AI-запросов

Из корня репозитория, в PowerShell; `.venv` предварительно создаётся командой `python -m venv .venv`, если отсутствует:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:MOCK = '1'
$env:COMMUNITY_DEMO = '1'
$env:SEED_DEMO = '1'
$env:DATABASE_PATH = 'data/runtime/community-demo.sqlite3'
$env:APP_PUBLIC_URL = 'http://127.0.0.1:8000'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000>. В разделе «Сотрудничество / Ынтымақтастық» выбираются пользователь и язык новых экранов. Синтетические аккаунты: заказчик `demo-business`, посторонний заказчик `other-business`, модератор `demo-moderator`, капитан и участник каждой команды. Их идентификаторы возвращает `GET /api/community`; пароль в демо не нужен.

Для Linux/macOS используйте `./.venv/bin/python` и обычные переменные окружения. `MOCK=1` отключает внешние AI-вызовы, но HTTP API, ограничения, SQLite, личные копии и PDF работают по-настоящему. Seed добавляет недостающие учебные записи, не очищая существующую базу.

| Настройка | Назначение |
|---|---|
| `COMMUNITY_DEMO=1` | Открытый выбор учебной личности и создание серверной сессии; значение по умолчанию для демо |
| `COMMUNITY_DEMO=0` | Выбор отключён; ранее выданные демо-сессии также перестают давать доступ. Сам по себе этот флаг не устанавливает реальную систему входа |
| `DATABASE_PATH` | SQLite с вопросами, оценками, письмами, PDF, проверочными кодами и очередью уведомлений |
| `APP_PUBLIC_URL` | Канонический адрес сайта для QR и ссылок проверки; должен совпадать с адресом, доступным получателям |
| `MOCK` | `1` — явная шаблонная подсказка переноса ответа; `0` — попытка внешнего AI |
| `FALLBACK_TO_MOCK` | При `1` отказ AI допускает маркированный mock; при `0` возвращается ошибка без изменения карточки |
| `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_REASONING_EFFORT` | Основной провайдер выбора поля; общие настройки из `app/ai_config.py`, модель по умолчанию `gpt-5.5` |
| `NVIDIA_API_KEY`, `NVIDIA_MODEL` | Резерв выбора поля; модель по умолчанию `meta/llama-3.3-70b-instruct` |
| `AI_TIMEOUT_SECONDS`, `MAX_CALLS_PER_HOUR` | Тайм-аут провайдера и общий ограничитель AI-вызовов |
| `LLM_LOG_PATH` | Журнал режима, провайдера, ошибок и времени; по умолчанию `logs/llm_calls.jsonl` |
| `SPEC_PDF_FONT` | При необходимости путь к Unicode TTF; используются также доступные системные DejaVu Sans/Arial |

Секреты задаются только в окружении или локальном `.env`. Команды выше не меняют существующий `.env`.

## Как проверить в интерфейсе

### Вопросы и ответы

1. Выберите студента в «Сотрудничестве», откройте опубликованную задачу в каталоге и её вопросы. Введите 10–1000 символов, просмотрите найденные похожие вопросы и отправьте свой.
2. Переключитесь на другого студента: обычный вопрос виден той же карточке. Выберите владельца `demo-business`, ответьте и проверьте ответ у обеих команд. `other-business` не может отвечать за владельца.
3. Автор может исправить вопрос, пока у него статус `new`. После ответа доступна только правка ответа владельцем: предыдущий текст сохраняется в ревизиях, появляется отметка об изменении.
4. Для ответа выберите перенос в карточку. Проверьте предлагаемое поле и дословный ответ; при необходимости отредактируйте текст. Перенос меняет рабочую версию, снимает подтверждение поля и требует последующего подтверждения и публикации на экране бизнеса. Каталог до публикации сохраняет прежние условия.
5. Проверьте фильтры, подписку и ссылку дубликата. Отклонённый вопрос с причиной виден только автору; скрытый — автору и модератору. Поиск похожих соблюдает те же права. Шестой вопрос одного студента на одну карточку в те же сутки UTC отклоняется сервером.

Каждый ответ единственный для вопроса; его изменение создаёт историю, а не второй ответ. Дубликат ссылается на исходный вопрос этой карточки, цепочки и циклы запрещены. Вопросы со статусами `answered`, `duplicate`, `declined`, `hidden` не возвращаются в `new` через редактирование.

### Проект и письмо

1. Отправьте отклик и выберите команду обычным действием бизнеса. Из выбранного отклика откройте проект. На одну пару «карточка — команда» создаётся один проект, даже если откликов несколько.
2. Капитан задаёт состав и роли до завершения проекта. Переключитесь на каждого участника, который должен попасть в письмо, и подтвердите его роль. Изменение роли снимает подтверждение; устаревшее подтверждение отклоняется.
3. Заказчик закрывает проект. `completed` требует принятого проверяемого этапа; прежние +10 сами по себе не служат доказательством выполнения. `closed_early` фиксирует досрочное закрытие. Текущий проект использует один существующий этап прототипа, а не универсальный трекер этапов.
4. После закрытия откроется опросник на 30 дней. Укажите выполненную работу и конкретный пример результата длиной 50–500 символов в вопросе 2. В вопросе 3 — до трёх сильных сторон, в вопросе 8 — до двух подтверждённых участников; свободный комментарий — до 1000 символов. Ответ «нет» в вопросе 6 сохраняет оценку, но не создаёт письмо.
5. Сохраните ответы и откройте предпросмотр. Нажатие на предложение переводит к исходному ответу или комментарию. Прямой правки тела письма нет. Укажите имя и должность подписанта, выдайте письмо.
6. У каждого подтверждённого участника появится личная копия с его именем, ролью, собственным QR и ссылкой проверки. Скачайте PDF и проверьте ссылку. В портфолио копия включается самим владельцем; первоначально она скрыта.
7. Исправление выдаётся новой версией по актуальному предпросмотру: старая получает `replaced`. Отзыв даёт статус `revoked`. Исходные PDF остаются неизменными. Получатель может отправить модератору сообщение об ошибке в фактах.

Подтверждение ролей после закрытия недоступно: проверьте состав заранее. При отсутствии хотя бы одного подтверждённого участника письмо не создаётся. Ответы опросника доступны заказчику и модератору; публичный профиль команды отдаёт только судьбу прототипа и комментарий к вопросу 1 после согласия капитана от имени команды.

## Где AI, а где вычисления

Выбор поля для переноса ответа реализован в [question_suggestion.py](../app/question_suggestion.py). При `MOCK=0` цепочка фиксирована: **OpenAI → NVIDIA → маркированный mock**, если последний разрешён. В модель передаются только вопрос и ответ, не полный черновик карточки. Модель может вернуть только одно имя поля из схемы. Сам текст предложения сервер берёт дословно из ответа; добавление новых утверждений в этом шаге не разрешено. Пользователь отдельно принимает перенос, затем подтверждает поле и публикацию. После внешнего вызова версии проверяются повторно.

Поиск похожих вопросов — локальное сравнение слов видимых вопросов и ответов, до пяти совпадений. Это не семантический поиск и не гарантия обнаружения перефразированного дубликата.

Письмо собирается **детерминированно** из версионируемых RU/KK/EN-фраз; API сообщает `mode: "template"`, `ai_used: false`. Каждый блок основного текста хранит источник: вопрос, выбранный вариант или комментарий и версию шаблона. Комментарии очищаются от HTML и далее вставляются дословно на исходном языке. Они не переводятся автоматически: это сознательное ограничение, чтобы перевод не изменил утверждения заказчика. Вопрос 7 с ответом «нет» в письмо не включается. Даты берутся из записей проекта и приёмки; соблюдение сроков без согласованного календарного плана не выдумывается.

Новые экраны имеют русский и казахский варианты; переключатель языка не является переводом всего ранее существовавшего приложения. Для письма отдельно выбирается русский, казахский или английский. Реальные внешние вызовы именно нового AI-выбора поля в этой работе не выполнялись: тесты проверяют контракт SDK и отказы заглушками. Проверки более раннего AI-интервью из README не являются подтверждением нового сценария.

## Сессии, права и сохранность

Новые защищённые API используют случайную серверную сессию в cookie `sana_session`: HttpOnly, SameSite=Strict, срок 12 часов; в SQLite хранится хеш токена. Изменяющий запрос также требует заголовок `X-Community-Request: 1`. Идентификатор автора, компания и команда берутся из серверной записи пользователя. Заголовок `X-Demo-Role` не предоставляет права в новых API.

Это всё ещё открытое демо: при включённом переключателе любой посетитель может выбрать учебного владельца или модератора. Старые действия конструктора/каталога сохраняют прежние открытые демо-роли. Выключение `COMMUNITY_DEMO` не превращает приложение целиком в систему защиты конфиденциальных данных; самостоятельная регистрация, проверка личности и производственная интеграция входа здесь не реализованы.

Правки вопроса и ответа передают `version`; перенос — `card_revision` и `answer_version`. Подтверждение роли передаёт увиденное `expected_role`. Выдача использует сохранённый предпросмотр; перевыпуск — его `draft_id`. При несовпадении версии сервер возвращает конфликт и не подтверждает новое содержание автоматически. Лимиты, единственность ответа, выпуск всех личных копий и журнал действий записываются транзакционно.

PDF формируется из зафиксированных данных и хранится как неизменяемый объект в SQLite вместе с SHA-256. QR использует только `APP_PUBLIC_URL`, а не заголовок Host клиента. Изменение этой настройки не переписывает старые PDF. Проверочная ссылка с непредсказуемым кодом доступна без сессии и показывает сведения о названной копии и текущий статус; любой получивший ссылку сможет её проверить. Скрытие из портфолио не отзывает письмо и не отключает проверку.

Для сохранения работоспособности выданных QR необходимы **постоянная база, резервное копирование и стабильный публичный адрес**. [render.yaml](../render.yaml) не выделяет постоянный диск; состояние такого размещения временное. Пока постоянный диск фактического сервиса не подтверждён, данные Render следует считать временными. Потеря SQLite означает потерю кодов проверки, писем и истории. Локальный файл сохраняется при перезапуске; для Docker подключите постоянный том к пути базы.

## Уведомления и время

Доставка только внутри раздела «Сотрудничество»: email, SMS и внешние мессенджеры не подключены. Событие создаёт запись transactional outbox в той же SQLite-транзакции; повторная обработка не создаёт повторное уведомление. Обработчик запускается раз в минуту и при открытии входящих; поэтому это не обещание доставки точно в секунду.

| Событие | Получатель и правило |
|---|---|
| Новый вопрос | Представители компании-владельца; один дайджест на следующей границе часа UTC |
| Вопрос остаётся `new` 72 часа | Владельцы компании; одно напоминание на вопрос |
| Первый ответ | Автор вопроса и текущие подписчики карточки, без дублирования автора |
| Отклонение | Автор вопроса |
| Нет отправленного опросника | Заказчик на 3-й, 7-й и 14-й день после закрытия, в пределах 30-дневного окна |
| Выдача/отзыв письма | Владельцы личных копий |
| Жалоба на факты | Модераторы |

После простоя обработчик опросника отправляет только последнее наступившее напоминание, не все пропущенные сразу. Черновая запись без `submitted_at` не считается отправленным опросником. Очередь и отметки доставки переживают перезапуск при сохранении базы. Суточный лимит вопросов использует календарные сутки UTC, независимо от часового пояса браузера.

## API для интеграции

Точные схемы доступны в `/docs`. Все перечисленные защищённые методы требуют сессию; изменяющие — также `X-Community-Request: 1`. Проверка письма, публичное портфолио и разрешённые командой сведения открыты без сессии.

| Метод | Назначение / тело запроса |
|---|---|
| `GET /api/community` | Демо-режим, доступные учебные пользователи и текущий actor |
| `POST /api/community/session` | Выбор учебной личности: `{user_id}` |
| `GET /api/cards/{id}/questions` | Видимые вопросы; `filter=all\|answered\|unanswered`, `limit`, `offset`; ответ `{items,total,filtered_count,unanswered_count,subscribed,remaining_today,can_ask}` |
| `POST /api/cards/{id}/questions` | `{text}`; автор и команда берутся из сессии |
| `GET /api/cards/{id}/questions/similar?q=...` | `{items,method:"lexical"}` с проверкой видимости |
| `GET /api/questions/{qid}` | Видимый вопрос по прямой ссылке, независимо от страницы списка |
| `PATCH /api/questions/{qid}` | `{text,version}`; только автор нового вопроса |
| `POST /api/questions/{qid}/answer` | `{text}`; только компания-владелец |
| `PATCH /api/questions/{qid}/answer` | `{text,version}`; сохраняется предыдущая ревизия |
| `POST /api/questions/{qid}/decline` | `{reason,version}`; причина доступна автору |
| `POST /api/questions/{qid}/merge` | `{duplicate_of_id,version}`; только исходный вопрос той же карточки |
| `POST /api/questions/{qid}/hide` | `{reason,version}`; только модератор |
| `POST /api/cards/{id}/subscribe` | `{subscribed}`; собственная подписка студента |
| `POST /api/questions/{qid}/suggest-field` | `{field,text,mode,provider,card_revision,answer_version}`; без изменения карточки |
| `POST /api/questions/{qid}/apply-field` | `{field,text,card_revision,answer_version}`; снимает подтверждение, не публикует |
| `GET\|POST /api/proposals/{id}/project` | Получить / создать проект выбранной команды |
| `GET /api/projects`, `GET /api/projects/{id}` | Проекты и данные, доступные текущему actor |
| `PUT /api/projects/{id}/roles` | `{members:[{user_id,role}]}`; капитан, до закрытия |
| `POST /api/projects/{id}/roles/confirm` | `{expected_role}`; участник подтверждает только свою показанную роль |
| `POST /api/projects/{id}/close` | `{status:"completed"\|"closed_early"}`; компания-владелец |
| `GET /api/projects/{id}/questionnaire` | Версионируемый шаблон, сохранённая оценка, срок, подтверждённые участники |
| `PUT /api/projects/{id}/assessment` | `{answers,comments,highlighted_user_ids}`; `answers` содержит ровно q1–q7, q2/q3 — массивы |
| `GET /api/projects/{id}/letter/preview?language=ru` | Сохранённый предпросмотр с ID и источниками фраз; языки `ru`, `kk`, `en` |
| `POST /api/letters/{lid}/issue` | ID предпросмотра; `{signer_name,signer_position}` |
| `POST /api/letters/{lid}/reissue` | ID предыдущего письма; `{draft_id,signer_name,signer_position,language}` |
| `POST /api/letters/{lid}/revoke` | `{reason}`; отзыв всей версии с её копиями |
| `GET /api/me/letter-copies` | Собственные копии и ссылки скачивания/проверки |
| `GET /api/letter-copies/{cid}/pdf` | Сохранённый PDF; получатель, заказчик или модератор |
| `PATCH /api/letter-copies/{cid}/visibility` | `{show_in_portfolio}`; только получатель |
| `POST /api/letter-copies/{cid}/complaint` | `{text}`; только получатель |
| `GET /api/letter-complaints` | Полные тексты жалоб, только модератору |
| `PUT /api/projects/{id}/public-consent` | `{public_consent}`; капитан команды |
| `GET /api/users/{id}/portfolio` | Только копии, открытые их владельцем |
| `GET /api/teams/{id}/project-recommendations` | Только q5 и комментарий q1, если команда согласилась |
| `GET /profiles/users/{id}`, `GET /profiles/teams/{id}` | Публичные страницы с теми же ограничениями; ссылки из интерфейса |
| `GET /verify/{code}`, `GET /api/verify/{code}` | HTML / JSON актуального статуса копии |
| `GET /api/notifications`, `POST /api/notifications/{id}/read` | Собственные входящие и отметка прочтения |
| `GET /api/community/audit` | Журнал действий; только модератор |

После заполнения опросника в отведённые 30 дней сохранённая оценка остаётся основанием для предпросмотра и выдачи. Изменение самой оценки после срока запрещено. Каждая повторная выдача требует нового актуального предпросмотра; исходный выпуск не перезаписывается.

## Проверки и соответствие приёмке

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pytest -q tests/test_questions.py tests/test_community.py tests/test_question_suggestion.py tests/test_project_letters.py
```

Тесты используют отдельные временные SQLite-базы. Для проверки сроков подменяется время внутри теста; системные часы и реальные пользовательские даты не меняются. AI-провайдеры заменяются тестовыми клиентами. Проверка скорости PDF измеряет локальный тестовый сценарий, а не гарантирует SLA размещения или максимального состава в 50 человек.

Браузерный smoke вопросов выполняется на отдельно запущенном локальном сервере с `MOCK=1` и учебными данными. Smoke писем ниже сам поднимает временный сервер с отдельной базой на свободном порту 8009. Нужен установленный Edge. Playwright — инструмент проверок, не зависимость приложения:

```powershell
.\.venv\Scripts\python.exe -m pip install playwright==1.63.0
.\.venv\Scripts\python.exe scripts/smoke_questions.py --url http://127.0.0.1:8000
.\.venv\Scripts\python.exe scripts/smoke_project_letters.py --url http://127.0.0.1:8009 --serve-isolated
```

Smoke создаёт и изменяет учебные записи; используйте отдельную локальную базу. Команды здесь описывают воспроизводимую проверку, не подтверждают запуск на публичном сервисе. Итог конкретного прогона нужно сверять с его выводом и сохранёнными артефактами.

| Критерий PDF-ТЗ | Реализация и автоматическая проверка |
|---|---|
| Вопрос только в опубликованной карточке, не больше пяти в сутки | Серверная проверка снимка, личности и UTC-дня; конкурентные запросы в `test_questions.py` |
| Ответ виден всем командам, перенос требует подтверждения | Общая видимость обычных вопросов; владелец компании; удаление подтверждения даже при равном тексте, опубликованный снимок сохраняется |
| Опросник только после завершения или досрочного закрытия | Проверка lifecycle и 30 дней; `completed` требует принятого этапа, не учебных баллов |
| Обязателен пример результата; «нет» запрещает письмо; только подтверждённые роли | Серверная валидация оценки, фильтрация получателей, защита от устаревшего подтверждения роли |
| Предложения связаны с ответами, новых утверждений нет | Версионируемые фразы и `sentences[].source`; комментарии дословно, шаблонный режим объявлен явно |
| Выданное письмо не меняется; проверка различает состояния | Замороженные PDF/источники, новая версия при исправлении, `valid/replaced/revoked`, тесты неизменности байтов |
| Права и журнал действий | Серверные sessions/ownership, CSRF-заголовок, аудит; тесты чужой компании, команды, копии и отключения демо |
| Уведомления и ограничения времени | Тесты часового дайджеста, 72 часов, 3/7/14 дней, повторов и перезапуска SQLite |
| RU/KK и PDF с QR до пяти секунд | Два языка новых экранов; RU/KK/EN шаблоны PDF, Unicode/QR и локальный замер времени |

Главные компромиссы относительно полноценной эксплуатации: открытая демонстрационная личность, один этап проекта, внутренние уведомления без внешней доставки, словарный поиск похожих вопросов, шаблонная сборка письма и отсутствие автоматического перевода свободных комментариев. Регистрация, производственное управление доступом, календарь этапов, обработка модератором полного жизненного цикла жалобы и эксплуатационный SLA не заявляются.
