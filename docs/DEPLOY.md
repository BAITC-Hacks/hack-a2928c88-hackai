# Размещение на Render

Капитан выбрал Render. Из-за недоступности приватного Git-репозитория в списке Render подготовлен путь Existing Image. Публичный адрес приложения ещё не получен.

Загруженный образ: `docker.io/denryyyyyyy/sana-hub:0ca1dc1` (приватный).
Digest: `sha256:4ba880a03fa16c5116324fd80238a7be54e30f2a8f9ac5f7b933e933e58bd348`.
Платформа linux/amd64, исходный коммит 0ca1dc1; включает каталог T-002, экран бизнеса T-001 ещё не включён. Пароли и .env в образ не входят. Для Render Credential нужен Docker Hub username `denryyyyyyy` и токен с правом чтения, вводимый только в интерфейсе Render.

## Если репозиторий не виден: готовый Docker-образ

Проверено через GitHub: выданный репозиторий PRIVATE, у текущего пользователя WRITE. Подключение Public Git Repository URL здесь не подходит. Отсутствие в списке может быть связано с доступом интеграции Render к организации; наличие WRITE само по себе не подтверждает разрешение GitHub App.

Можно обойти Git-интеграцию, передав Render образ приложения. Исходники продолжаем коммитить только в выданный Git-репозиторий. Для приватных исходников используем приватный реестр; публичность не меняем автоматически.

1. Создайте приватный репозиторий образов, например `docker.io/ВАШ_ЛОГИН/sana-hub`, и выполните `docker login` в своём терминале.
2. Соберите и загрузите из этого checkout:

   ```powershell
   .\scripts\build-image.ps1 -Image docker.io/ВАШ_ЛОГИН/sana-hub -Push
   ```

   Без `-Push` скрипт только собирает локально. Фактический логин должен быть в нижнем регистре. Образ получает тег по коммиту, платформа linux/amd64. `.env` и ключи не включаются; Dockerfile копирует только приложение, зависимости и синтетические данные.
3. Render → New → Web Service → Existing Image. Вставьте напечатанную ссылку на образ. В Credential добавьте логин и токен реестра для чтения приватного образа через интерфейс Render.
4. Задайте `MOCK=1`, `FALLBACK_TO_MOCK=1`, `SEED_DEMO=1`, `DATABASE_PATH=/data/sana.sqlite3`. Health check: `/health`. Команда запуска уже записана в образе; слушает `0.0.0.0:$PORT`.
5. После Deploy пришлите только публичный URL приложения. Локальный образ или tar-файл напрямую в Render не загружается: нужен доступный образ в реестре.

При обновлении соберите и отправьте новый тег, укажите его в сервисе Render и запустите деплой. Сервисы Existing Image не обновляются автоматически от git push или изменения образа. [Официальные инструкции Render](https://render.com/docs/deploying-an-image).

## Если доступ GitHub App удалось выдать

1. В Render откройте New → Blueprint, подключите BAITC-Hacks/hack-a2928c88-hackai, ветку main. Конфигурация — render.yaml в корне.
2. Проверьте Docker runtime, health check /health, MOCK=1 и SEED_DEMO=1. Не создавайте Static Site: приложению нужен Python backend.
3. После статуса Live откройте URL сервиса и /health. Из локального окружения выполните `python scripts/smoke_url.py https://АДРЕС.onrender.com`. Скрипт только читает данные.
4. Передайте адрес ведущему для проверки и добавления в README. Сквозной сценарий браузера проверяется отдельно.

Текущий Blueprint использует free и **не создаёт постоянный диск**. SQLite будет теряться при перезапуске/повторном развёртывании, после чего загрузятся синтетические примеры. Free-сервис также засыпает при отсутствии запросов; постоянный диск на free недоступен. Для сохранения данных и доступности во время судейства нужен подходящий платный сервис и диск /data. Не меняйте тариф без решения капитана. [Ограничения Render Free](https://render.com/docs/free), [Blueprint reference](https://render.com/docs/blueprint-spec).

Для реального AI в Environment задайте OPENAI_API_KEY, MOCK=0, OPENAI_MODEL; при необходимости NVIDIA_API_KEY и NVIDIA_MODEL. FALLBACK_TO_MOCK=1 оставляет явный резерв при ошибках. Ключи в Git и чат не копируйте. После изменения режима нужна проверка новой карточки: /health показывает конфигурацию, фактический провайдер отражён в результате карточки.

Проверено локально: Docker build Python 3.12, старт контейнера, health, синтетический каталог, API-адаптер; браузерный сценарий каталога проверен в Edge с локальным Python-сервером. Это не подтверждение внешнего деплоя.
