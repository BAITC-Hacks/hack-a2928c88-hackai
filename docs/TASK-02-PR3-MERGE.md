**Приоритет сейчас:** довести существующий [PR #3](https://github.com/BAITC-Hacks/hack-a2928c88-hackai/pull/3) до готовности к ревью. Новый PR не создавать.

Ветка: `team/catalog-ui`. Конфликты: `app/static/catalog.js`, `app/static/catalog.css`. Менять только эти два файла. Claude не вызывать.

## Почему возник конфликт

В main уже влит редизайн (`e229006`, PR #2). Он меняет устройство каталога и добавляет серверный поиск/пагинацию, фильтры, рекомендации, панель подробностей и сравнение откликов. Ваша ветка добавляет полезные исправления и insights поверх старого интерфейса.

**Основа итогового экрана — новый дизайн из main.** В него перенести ваши исправления, защиту ввода и отображение insights. Не выбирать целиком ours/theirs и не возвращать старый каталог.

Это ТЗ заменяет устаревшие указания TASK-02-INNOVATION.md о локальной пагинации и загрузке всех карточек ради списка отраслей. Серверные методы уже реализованы в main.

## 1. Обновить свою ветку

Сначала сохранить незакоммиченные изменения. Затем:

```powershell
git switch team/catalog-ui
git fetch origin
git merge origin/main
```

Разрешить конфликты вручную. Без reset, force push, переписывания main и правок чужих модулей. В рабочей ветке после merge должны присутствовать оба набора изменений.

## 2. Сохранить из main

- Оформление, шкалы готовности, фильтры-чипы, выбор профиля команды.
- Поиск и страницы через `api.listCardsPage({q, industry, level, limit:20, offset})` → `{items,total}`. Не создавать второй клиентский механизм пагинации.
- Список отраслей и счётчики через `api.catalogFacets()`, а не загрузкой 413 карточек.
- Рекомендации через `api.teamRecommendations(teamId, limit)`; они не ограничивают общий каталог и не назначают команды.
- Панель подробностей и вкладки задачи/отклика/решений, показ источников, сравнение откликов и ручные решения.
- Экспорт `mountCatalog(root, api)` и возврат **`{refresh, focusCard}`**. `focusCard(card)` используется общей страницей после публикации; его потеря сломает сквозной сценарий.
- Совместимость CSS с общей темой `ui.css`. Общую тему и index.html не менять.

## 3. Перенести из своей ветки

### Обязательная ссылка и сохранность отклика

- Ссылка на прототип обязательна, только непустой HTTP(S) URL. Ошибка рядом с полем до отправки запроса.
- Идея, план, срок, ссылка и выбранная команда сохраняются при ошибке отправки и перерисовке.
- Черновик привязан к ID задачи: не переносить текст отклика на другую задачу случайно.
- Переключение вкладок, закрытие/открытие панели, refresh и смена страницы не должны молча уничтожать текст. Сохранять черновик в памяти; перед действием, которое действительно его потеряет, показывать предупреждение.
- Успешная отправка очищает только черновик отправленного отклика. Двойной клик не создаёт дубликат.
- Сохранить доступные подписи и сообщения ошибок.

### Insights в новом оформлении

Перенести `currentInsights`, `positionLabel`, `improvementSection`, `reviewSection` либо эквивалентную логику в новый экран:

- Глобальное место — только из серверного `catalog_insights`; индекс страницы не является местом в общем каталоге.
- До трёх отдельных действий с условной прибавкой и прогнозом после подтверждения/публикации. Не складывать сценарии и не считать рейтинг в JS.
- До трёх замечаний с цитатой, вопросом и пометкой AI-предположения либо проверки правилом.
- Проверять revision карточки и анализа; устаревшие данные явно обозначать.
- Без `catalog_insights` показывать нейтральную недоступность. Не подставлять демонстрационные числа или замечания в продукт.
- Сохранить все состояния из TASK-02-INNOVATION.md: not_run / complete / stale / unavailable, live/mock, пустой список замечаний.
- Пользовательские и AI-строки выводить через `textContent`. Замечания не меняют сортировку и не блокируют отклик.

Новый backend insights остаётся задачей Codex. Готовность верстки этих блоков не объявлять готовностью серверного анализа. Самостоятельно не менять api.js, main.py или схему.

## 4. Проверить объединённую версию

Использовать отдельную локальную учебную базу, не публичный Render:

```powershell
$env:MOCK='1'
$env:DATABASE_PATH='data/runtime/catalog-pr3-check.sqlite3'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8006
```

Во втором терминале:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/smoke_catalog.py --url http://127.0.0.1:8006
.\.venv\Scripts\python.exe scripts/smoke_e2e.py --url http://127.0.0.1:8006 --mode mock
```

Ручная приёмка:

1. Новый дизайн сохранён; нет ошибок консоли и конфликтных маркеров.
2. Поиск, отрасль и уровень работают вместе; страницы по 20, корректный total, пустой результат и сброс. Порядок сервера сохранён.
3. Рекомендации не закрывают общий список. Задача <40 доступна для отклика.
4. Ввести отклик, переключить вкладку, закрыть панель и открыть ту же задачу: текст сохранён. При открытии другой задачи он не подставляется в её форму.
5. Пустая/некорректная ссылка не отправляется. Ошибка API сохраняет весь ввод; повтор после восстановления работает.
6. Можно выбрать несколько команд или отклонить все. Повторное подтверждение этапа не даёт вторые +10.
7. Публикация на экране бизнеса переводит к нужной карточке через focusCard.
8. Без insights каталог полностью работает. С отдельной тестовой фикстурой проверены актуальная/устаревшая версии и все состояния review. Указать, что это проверка фикстуры, а не живого backend.

Если тест обнаружил проблему вне своих файлов — передать вывод ведущему, не исправлять чужой код. Не подгонять тесты, удаляя проверки.
