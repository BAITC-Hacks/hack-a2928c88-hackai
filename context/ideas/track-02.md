# Идея — трек 2: GovTech

Черновик по шаблону `IDEA_CANVAS.md`. Основан на рабочей гипотезе из `claude_2.md` (21.09.2026). **Не официальный кейс** — после получения кейса сверить и переписать (prompts/00-kickoff.md).

## Название
ОтветОК — проверка полноты ответа на обращение

## Пользователь и боль
- Кто: Специалист госоргана, готовящий ответ гражданину
- Боль: <что делает сейчас, сколько времени, где ошибается — заполнить из кейса>

## Одна фраза решения
«<Пользователь> загружает <вход>, агент <действие> и возвращает <выход с доказательствами>, пользователь подтверждает, в результате <измеримый эффект>.» — заполнить после чтения кейса.

## Вход → выход
- Вход: Обезличенное обращение + проект ответа (+ выдержки из НПА/регламента)
- Выход: Список вопросов заявителя: раскрыт/не раскрыт в ответе, ссылки на фрагменты, черновик недостающих пояснений

## Шаги агента
1. Извлечь все вопросы/требования из обращения
2. Сопоставить каждый с фрагментом ответа
3. Правила: сроки ответа, обязательные реквизиты, язык обращения = язык ответа
4. Сотрудник подтверждает, экспорт карточки

## Что проверяет код (app/rules.py)
- срок ответа от даты регистрации
- обязательные реквизиты ответа
- язык ответа совпадает с языком обращения

## Проверка
- Набор: 15–20 пар обращение/ответ с ручной разметкой полноты; recall пропущенных вопросов
- Бейзлайн: модель «оцени ответ» одним запросом

## Не заявлять
юридическую правильность; интеграцию с e-Otinish

## Запасные идеи трека
- Маршрутизатор обращений по ведомствам с объяснением
- Упрощение ответа до понятного языка с сохранением смысла
