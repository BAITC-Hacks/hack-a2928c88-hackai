# Sana Hub — «Паспорт готовности»

**HackAlem AI · трек 07 «Образование» · AI Sana Challenge Hub**

Sana Hub помогает бизнесу превратить короткое описание проблемы в понятную задачу для студенческой команды. Главная механика — прозрачный рейтинг готовности: бизнес дополняет и подтверждает сведения, видит начисленные баллы и понимает, чего ещё не хватает.

**Текущее состояние:** реализованы модели данных, расчёт рейтинга и тестовый набор. Веб-интерфейс, HTTP API, продуктовые вызовы AI и публичный деплой ещё не реализованы. Инструкции ниже позволяют запустить и проверить готовую программную основу.

## 1. Что делает проект

Целевой пользователь — представитель бизнеса, которому нужна помощь студентов, но пока не хватает полноценного описания задачи.

Планируемый сквозной сценарий:

1. Бизнес вводит краткое описание потребности.
2. AI определяет пробелы и задаёт минимум три уместных уточняющих вопроса.
3. Из ответов формируется редактируемая карточка с источниками сведений.
4. Человек проверяет и подтверждает карточку; код рассчитывает рейтинг от 0 до 100.
5. Задача публикуется в общем каталоге с сортировкой по рейтингу.
6. Студенческие команды самостоятельно отправляют предложения.
7. Бизнес вручную выбирает одну, несколько или ни одной команды.

Низкий рейтинг по условиям кейса не должен скрывать опубликованную задачу или запрещать отклик. AI не выбирает исполнителей, не подтверждает поля и не должен добавлять факты от себя.

Полное задание: [docs/CASE.md](docs/CASE.md). Продуктовая идея: [docs/IDEA.md](docs/IDEA.md).

### Действующая формула рейтинга

Рейтинг вычисляется в [app/rating.py](app/rating.py), без вызовов модели.

| Критерий | Максимум | Начисление в текущем коде |
|---|---:|---|
| Контекст и потребность | 20 | `context` — 10, `need` — 10 |
| Данные и материалы | 20 | `data` — 20 |
| Ожидаемый результат | 15 | `expected_result` — 15 |
| Критерии успеха | 15 | `success_criteria` — 15 |
| Ограничения | 10 | `constraints` — 10 |
| Пользователи | 10 | `users` — 10 |
| Связь с бизнесом | 10 | `contact` — 4, `interaction_format` — 3, `feedback_process` — 3 |
| **Итого** | **100** | Сумма зачтённых компонентов |

Компонент засчитывается, если поле непустое и его текущее значение точно совпадает с подтверждённым. Неподтверждённый текст даёт 0. Название карточки баллов не добавляет. Подтверждение хранит значение и идентификатор подтвердившего пользователя; само по себе оно не является механизмом авторизации.

| Баллы | Уровень | Значение в API-контракте |
|---|---|---|
| 0–39 | Черновик | `draft` |
| 40–69 | Рабочая | `working` |
| 70–89 | Готовая | `ready` |
| 90–100 | Приоритетная | `priority` |

`recommended_eligible` становится `true` от 40 баллов; это признак для будущих рекомендаций, а не запрет просмотра или отклика.

Рейтинг сейчас измеряет **подтверждённую заполненность**, а не истинность фактов или качество бизнес-идеи. Расширенная рубрика с подполями и зависимостями предложена в архитектуре, но ещё не перенесена в код. Таблица выше описывает реально работающую версию.

## 3. Технологии и архитектура

Работающая основа:

- **Python 3.10+** — доменная логика; проверено на Python 3.10.
- **Pydantic 2.13.5** — модели, ограничения полей и валидация.
- **pytest 9.1.1** — автоматические проверки.
- **JSON** — синтетические данные и рассчитанные рейтинги.

```text
TaskCard + подтверждения значений
                │
                ▼
       app/rating.py — правила кодом
                │
                ▼
RatingBreakdown: сумма, уровень, начисления, недостающее
```

Предложенная архитектура веб-MVP: одна HTML-страница с JavaScript/CSS → FastAPI → доменные правила и SQLite. Отдельный AI-модуль будет задавать вопросы и предлагать карточку, сохраняя обязательное подтверждение человеком. Этот слой пока не реализован и не входит в текущие зависимости.

```text
app/
  schemas.py              Модели и контракты данных
  rating.py               Расчёт, подтверждение и изменение карточки
tests/
  test_rating.py          Формула, границы уровней, подтверждения и схемы
  test_demo_data.py       Состав набора, связи записей, пересчёт баллов
  test_agent_answers.py   Обработка ответов агентов разработки
data/samples/
  ai-sana-synthetic.json  Учебные данные
docs/
  CASE.md                 Официальный текст кейса
  IDEA.md                 Идея и границы MVP
  ARCHITECTURE.md         Предложение архитектурного совета
  TEAM.md                 Задачи разработчиков и интерфейс адаптера
  DEMO_SCRIPT.md          План демонстрации
```

Исторические материалы `context/` относятся к прежнему списку треков. Для текущего трека 07 используйте `docs/CASE.md`: старый `context/ideas/track-07.md` описывает финтех и не является заданием этого проекта.

## 4. Установка и запуск

Нужны Git и Python 3.10 или новее. Запускайте команды из корня репозитория. Для установки пакетов требуется доступ к PyPI; для тестов и расчёта рейтинга интернет, API-ключи и база данных не нужны.

```bash
git clone https://github.com/BAITC-Hacks/hack-a2928c88-hackai.git
cd hack-a2928c88-hackai
```

**Windows PowerShell:**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

**Linux / macOS:**

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements-dev.txt
./.venv/bin/python -m pytest -q
```

`requirements-dev.txt` включает основные зависимости из `requirements.txt`. Для использования только доменных моделей и рейтинга достаточно установить `requirements.txt`.

**Серверной команды запуска пока нет:** `app/main.py` и веб-приложение ещё не созданы. Текущая версия запускается как Python-модуль через пример ниже и набор тестов.

## 5. Пример проверки

В PowerShell выполните:

```powershell
.\.venv\Scripts\python.exe -c "from app.schemas import TaskCard; from app.rating import calculate_rating, confirm_fields, edit_card; c = TaskCard(draft_id='demo-1', industry='retail', context='Requests arrive by email', data='Anonymized CSV', synthetic=True); print(calculate_rating(c).total); c = confirm_fields(c, ['context', 'data'], business_actor='demo-business'); print(calculate_rating(c).total); c = edit_card(c, {'context': 'Requests arrive by phone'}); print(calculate_rating(c).total)"
```

Для Linux/macOS замените `.\.venv\Scripts\python.exe` на `./.venv/bin/python`, сохранив аргумент `-c`.

Ожидаемый вывод:

```text
0
30
20
```

Объяснение:

1. Заполненная, но неподтверждённая карточка получает **0**.
2. Подтверждение контекста (+10) и данных (+20) даёт **30**.
3. Изменение контекста снимает его подтверждение; подтверждённые данные сохраняют **20**.

Полный набор проверок (`python -m pytest -q` в виртуальном окружении) сейчас даёт **26 passed**. Проверяются точные веса, пороги 39/40, 69/70 и 89/90, отсутствие начислений до подтверждения, изменение текста, валидация AI-контракта, ссылок и синтетического набора. Это тесты основы, а не подтверждение работающего сквозного веб-сценария.

## 6. Данные и внешние сервисы

[data/samples/ai-sana-synthetic.json](data/samples/ai-sana-synthetic.json) содержит:

- 5 бизнес-черновиков разной полноты;
- 5 карточек с подтверждениями и расшифровками рейтинга;
- 5 профилей команд: название, интересы, навыки и технологии;
- 5 предложений: команда, задача, идея, план, срок и ссылка.

Все записи помечены `synthetic: true`. Карточки — подготовленный вручную учебный эталон, **не автоматически подтверждённый вывод AI**. Их рейтинги текущей формулой: T1 — 49, T2 — 34, T3 — 67, T4 — 82, T5 — 100. Дополнительные сведения T1 относятся к ответам после уточнения; их нельзя извлечь из одного слабого черновика D1.

Организации, контакты и сведения вымышлены. Адреса `example.com` — демонстрационные ссылки, не действующие прототипы. Реальные персональные или клиентские данные для проверки не требуются.

**Внешние сервисы текущей программы:** отсутствуют. Для будущего AI-слоя запланированы OpenAI, резервный NVIDIA API и явно обозначенный mock; они пока не подключены. Ключи для текущего запуска не нужны.

**Инструменты разработки:** Codex — код и интеграция; Claude — идеи, демо, данные и ревью. Эти вызовы агентов не являются продуктовой AI-функцией. Предсуществующий harness и зависимости раскрыты в [docs/DISCLOSURE.md](docs/DISCLOSURE.md), вклад Codex — в [docs/CODEX_LOG.md](docs/CODEX_LOG.md).

## 7. Известные ограничения

- Сквозной сценарий публикации, отклика и ручного выбора ещё не работает: готовы его модели, но не API и UI.
- Рейтинг не проверяет смысл, измеримость критерия успеха или правдивость подтверждённой информации. Непустое слабое описание может получить баллы.
- Схема `AISuggestion` проверяет структуру и минимум три различных вопроса, но не их уместность и не достоверность цитат. Проверка источников ещё предстоит.
- `confirmed_by` и `decided_by` — поля доменной модели, а не проверенные учётные записи. Авторизация и серверная проверка полномочий пока отсутствуют.
- Нет постоянного хранения, защиты от конфликтующих обновлений, начисления прогресса и проверки повторных запросов.
- Расширенная рубрика в `docs/ARCHITECTURE.md` — предложение следующего этапа; текущие код, данные и инструкция используют базовую формулу.
- Файловые readers, FastAPI, SQLite и AI-провайдеры из описания подготовленного harness пока не подключены к этому приложению.
- [docs/DEMO_SCRIPT.md](docs/DEMO_SCRIPT.md) описывает целевую демонстрацию, а не уже пройденную приёмку.
