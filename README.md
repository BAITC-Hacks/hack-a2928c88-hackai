# Sana Hub — «Паспорт готовности»

**HackAlem AI · трек 07 «Образование» · AI Sana Challenge Hub**

**Демо:** [sana-hub-0ca1dc1.onrender.com](https://sana-hub-0ca1dc1.onrender.com/) · [API](https://sana-hub-0ca1dc1.onrender.com/docs). Полный сценарий с реальным OpenAI повторно проверен на публичном сайте 23.09.2026 после редизайна. Восстановление карточки и новый цикл приёмки этапа пока проверены локально; требуют обновления образа Render.

## 1. Что делает проект

Sana Hub помогает бизнесу превратить описание проблемы в задачу для студентов: уточняющие вопросы → карточка с цитатами → подтверждение человеком → прозрачный рейтинг → публикация → отклики → ручной выбор команды → баллы за подтверждённый этап.

Бизнес видит, каких сведений не хватает и за что начислены баллы. AI не выбирает команду и не подтверждает факты. Низкий рейтинг не запрещает публикацию подтверждённой карточки и получение откликов.

Официальный кейс: [docs/CASE.md](docs/CASE.md). Идея: [docs/IDEA.md](docs/IDEA.md).

PR #3 интегрирован. Backend `catalog_insights` подключён к каталогу: место и прогнозы относятся к опубликованным условиям и текущему составу каталога. Каждый прогноз — отдельное условное дополнение, а не обещание роста откликов. [Исходный анализ](docs/INNOVATION-REVIEW.md) сохранён как история предложений.

**«Что помешает начать?»** — отдельная проверка сохранённой карточки. AI возвращает возможные проблемы и вопросы, код проверяет дословные цитаты; пустые поля и несколько явно отложенных ответов определяются правилами. Кнопка «Уточнить поле» переводит к редактору. Правка делает анализ устаревшим, подтверждение неизменённого текста сохраняет его. Проверка не меняет поля, подтверждения, рейтинг и решения о командах. В каталог результат попадает при публикации; неопубликованные правки и замечания туда не переносятся.

**Вопросы и рекомендательные письма:** публичные вопросы в карточке, ответы владельца с историей и переносом в подтверждаемые поля; состав команды, опросник после проекта и личные PDF с QR-проверкой, перевыпуском и отзывом. Новые экраны доступны на русском и казахском, уведомления — внутри приложения. Используются открытые учебные аккаунты; письма собираются из версионируемых фраз, комментарии сохраняются на исходном языке. [Запуск, API, приёмка и ограничения хранения](docs/COMMUNITY.md). Новый сценарий не объявляется установленным на Render; реальный AI-выбор поля для него отдельно не проверен.

Действующая формула в [app/rating.py](app/rating.py):

| Критерий | Баллы | Поля |
|---|---:|---|
| Контекст и потребность | 20 | context 10 + need 10 |
| Данные и материалы | 20 | data |
| Ожидаемый результат | 15 | expected_result |
| Критерии успеха | 15 | success_criteria |
| Ограничения | 10 | constraints |
| Пользователи | 10 | users |
| Связь с бизнесом | 10 | contact 4 + interaction_format 3 + feedback_process 3 |

Уровни: 0–39 «Черновик», 40–69 «Рабочая», 70–89 «Готовая», 90–100 «Приоритетная». Название не даёт баллов. Подтверждение относится к точному значению; после изменения оно снимается. Расширенные подполя отложены, в проекте одна формула.

## 3. Технологии и архитектура

Python 3.10+ (проверено на 3.10), FastAPI/Uvicorn, Pydantic v2, SQLite, OpenAI SDK, Vanilla JS без сборки Node. Проверки: pytest и TestClient/httpx. Точные версии — requirements.txt и requirements-dev.txt. Docker использует Python 3.12.

```text
Экраны бизнеса / каталога → app/static/api.js → FastAPI
                              ├─ app/llm.py: извлечение цитат и вопросы
                              ├─ app/rating.py: формула и подтверждения
                              ├─ app/recommend.py: рекомендации по совпадениям слов
                              ├─ app/review.py: замечания с цитатами и контроль версии
                              ├─ app/insights.py: условные прогнозы позиции
                              └─ app/store.py: SQLite, транзакции и снимки
```

`If-Match` защищает правки от устаревшей версии. Отклик сохраняет условия опубликованной карточки. Уникальная запись этапа по задаче/команде исключает повторные +10 в одной транзакции. Баллы готовности и прогресса разделены.

Рекомендации — детерминированная эвристика по словам интересов, навыков и технологий, а не семантический AI-подбор. В рекомендации входят задачи с рейтингом от 40; задачи ниже 40 остаются в общем каталоге и принимают отклики. Команды система не ранжирует и не назначает.

Исторический context/track-07 относится к финтеху; актуальное задание — только docs/CASE.md.

## 4. Установка и запуск

Нужны Git и Python 3.10+. Команды из корня репозитория.

```powershell
git clone https://github.com/BAITC-Hacks/hack-a2928c88-hackai.git
cd hack-a2928c88-hackai
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
# Только при первом запуске: не перезаписывайте существующий .env
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Linux/macOS: `python3 -m venv .venv`, затем те же команды через `./.venv/bin/python`; копирование — `cp .env.example .env`.

Открыть http://127.0.0.1:8000 и документацию API http://127.0.0.1:8000/docs. Доступны экран бизнеса и вкладка «Командам». Публичный Render обновляется отдельно от локальной версии.

По умолчанию `MOCK=1`, `SEED_DEMO=1`: ключи не нужны. База `data/runtime/sana.sqlite3` сохраняется между запусками. При старте добавляются отсутствующие ID примеров, существующие записи и решения не перезаписываются. Повторный запуск не создаёт дубликатов. Для чистой базы задайте другой DATABASE_PATH.

Для реального OpenAI задайте в локальном .env `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-4.1-mini`, `MOCK=0`; перезапустите сервер. Проверка одним платным запросом на синтетике: `python scripts/check_ai.py`. Ключ не выводится. Для Render эти значения отдельно задаются в Environment; локальный .env туда не переносится.

Полный локальный браузерный сценарий: установите дополнительный инструмент `pip install playwright==1.63.0` (нужен установленный Edge), затем `python scripts/smoke_e2e.py --url http://127.0.0.1:8000 --mode mock`. Для сервера с MOCK=0 используйте `--mode live`: это два реальных AI-запроса. Скрипт создаёт учебные записи; по умолчанию допускает localhost, публичный запуск требует явного `--allow-remote`. До редизайна проверен результат: 0 → 100 → 80 → 100, публикация, новый отклик, ручной выбор, однократные +10. Для последней версии новый полный браузерный прогон ещё требуется.

Docker:

```bash
docker build -t sana-hub .
docker run --rm -p 8000:8000 -v sana-data:/data -e MOCK=1 sana-hub
```

Docker-образ собран, запуск контейнера и read-only API smoke проверены локально. Шаблон render.yaml без постоянного диска использует временное хранилище — для сохранения данных подключите диск к /data.

## 5. Пример проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pytest tests/test_api.py -q
```

API-тест проходит создание черновика → вопросы → ответы → карточку с нулём баллов → подтверждение → публикацию → редактирование со снятием подтверждения. Проверяет низкий рейтинг, отклик, ручной выбор нескольких команд, однократные +10, сохранение базы после перезапуска. Тесты не доказывают готовность экранов или публичного URL.

Проверки включают цитаты, гонку правки с анализом, устаревание, расчёт позиции и весь цикл ручной приёмки. В Edge пройдены полный mock-сценарий и `python scripts/smoke_review.py --url http://127.0.0.1:8000`: восстановление после F5 → замечание → переход к полю → правка → устаревание → ошибка/повтор → подтверждение → опубликованный анализ и место. Используйте отдельную локальную учебную базу и MOCK=1.

`python scripts/smoke_stages.py --url http://127.0.0.1:8000` проверяет фиксацию условий → отправку → доработку → повторную отправку → приёмку → F5 → отсутствие повторных баллов. После выбора команды откройте сохранённую карточку на экране бизнеса и блок первого этапа. Бизнес задаёт результат, пример входа и способ проверки; команда отправляет ссылку и пояснение; бизнес вручную принимает или возвращает с причиной. Роли демонстрационные, доступны в одном блоке. Условия сохраняются снимком и не меняются вслед за карточкой. Старые задачи без такого этапа сохраняют прежнюю кнопку +10; для определённого этапа она не обходит приёмку.

Диагностический AI-набор: `python scripts/eval_review.py --live` (12 платных запросов). [Отчёт](docs/EVAL-REVIEW.md): 11 реальных ответов, один fallback; совпадение ожидаемых полей 9/12. Это не процент точности: набор использован для настройки, семантика требует ручной оценки. [Первый прогон](docs/EVAL-REVIEW-BASELINE.md) сохранён для сравнения.

Короткая проверка формулы:

```powershell
.\.venv\Scripts\python.exe -c "from app.schemas import TaskCard; from app.rating import calculate_rating, confirm_fields, edit_card; c = TaskCard(draft_id='demo', industry='retail', context='Requests by email', data='Synthetic CSV', synthetic=True); print(calculate_rating(c).total); c = confirm_fields(c, ['context', 'data'], business_actor='demo-business'); print(calculate_rating(c).total); c = edit_card(c, {'context':'Requests by phone'}); print(calculate_rating(c).total)"
```

Результат: **0 → 30 → 20**. Подтверждение добавляет баллы, правка снимает баллы изменённого поля.

В `/docs` действия бизнеса требуют `X-Demo-Role: business`, отправка отклика — `team`. Для правки, подтверждения и публикации передайте `If-Match`, равный `revision` карточки. Адаптер api.js делает это автоматически. Это демонстрационные роли, а не настоящий логин.

## 6. Данные и внешние сервисы

[data/samples/ai-sana-synthetic.json](data/samples/ai-sana-synthetic.json): 413 черновиков, 413 карточек, 10 команд и 417 откликов, пометка `synthetic: true`. Сохранены 13 исходных кейсов Claude; добавлены 400 шаблонных сценариев (10 отраслей × 10 процессов × 4 степени полноты) и 400 связанных откликов. Баллы новых карточек: 20/50/75/100; это полнота описания, не качество решения.

Источники: `coord/notes/Q-132813-claude.md`, `data/samples/synthetic-extra-source.json` и `scripts/generate_synthetic_bulk.py`. Сборка и пересчёт баллов: `python scripts/prepare_demo_data.py`. Организации, контакты и команды вымышлены. example.com — демонстрационные ссылки. Упомянутые CSV и контрольные примеры описывают предполагаемые данные задачи: сами файлы не приложены. Готовые карточки — учебные эталоны с подтверждениями автора фикстур, не автоматически подтверждённый AI-вывод.

Обновление набора совместимо с прежней схемой SQLite. Перед обновлением постоянной базы сохраните резервную копию. Откат версии приложения не удаляет импортированные примеры; `SEED_DEMO=0` отключает последующие импорты. Данные пользователей автоматически не удаляются.

При `MOCK=0` используется OpenAI Responses Structured Outputs; при ошибке — NVIDIA chat completions, затем mock, если `FALLBACK_TO_MOCK=1`. Ключи только в окружении/.env. При отсутствии ключей оставьте MOCK=1. Внешним сервисам передаются введённый текст и ответы бизнеса. 23.09 проверены реальные вопросы и сборка карточки через OpenAI локально и на Render: provider=openai, mode=live. NVIDIA остаётся непроверенным резервом.

Для отдельного стресс-теста передаются текстовые поля карточки; цепочка — OpenAI → явно обозначенные mock-правила, без NVIDIA. При `FALLBACK_TO_MOCK=0` ошибка провайдера оставляет карточку нетронутой и даёт повторить запрос. Общий лимит AI-запросов используется вместе с извлечением. Логи содержат метаданные, а не текст карточки и не ключи. Замечания модели остаются предположениями даже при валидной цитате.

Промпт, схема обмена и правило R-QUOTE находятся в [app/llm.py](app/llm.py). [Документация OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Лимиты: 30 000 символов суммарного входа, MAX_CALLS_PER_HOUR запросов в процессе; таймаут AI_TIMEOUT_SECONDS на запрос провайдера.

Предсуществующий harness, модели и библиотеки раскрыты в [docs/DISCLOSURE.md](docs/DISCLOSURE.md). Инструменты разработки Codex/Claude не являются продуктовой AI-функцией. Gemini недоступен.

## 7. Известные ограничения

- Редизайн и API стресс-теста подтверждены на Render; восстановление карточки и новый цикл приёмки требуют установки нового образа.
- Рейтинг измеряет подтверждённую заполненность: слабое или неправдивое описание тоже может получить баллы. Стресс-тест — отдельные рекомендации, не сертификация готовности и не второй рейтинг.
- Совпадение цитаты не доказывает смысл и уместность поля; результат проверяет человек. Mock переносит текст и ответы по полям, не выполняет интеллектуальный разбор.
- Роли открыты для демо, нет аутентификации и изоляции компаний. Используйте учебные данные.
- SQLite и лимит вызовов рассчитаны на один процесс. В контейнере нужен постоянный том.
- Повторная сборка черновика возвращает уже созданную карточку; дальнейшие правки выполняются через редактор.
- Нет readers файлов, чата, календаря, полного трекера и автоматического выбора исполнителя. Текущий ввод — текст.
- В текущем интерфейсе ссылка на прототип обязательна; сохранность черновика отклика реализована в памяти страницы, не после закрытия браузера.
- Полный сценарий проверен локально автоматизированно; очная репетиция за пять минут и проверка обновлённого публичного сервиса ещё нужны.
