## Мелкие замечания (выпуск не блокируют)

1. **409 распознаётся по тексту.** `api.js:22-23` выбрасывает `Error` без `status`, поэтому проверка `e.status === 409` в `business.js:96` никогда не срабатывает. Сейчас спасает только regex. Если на бэкенде поменяют формулировку, сценарий перезагрузки молча сломается. Исправление: в `api.js` дописывать в ошибку статус (`err.status = response.status`).
2. **Сбой сети показывается по-английски.** Если `fetch` падает сам, в `api.js:10` это не обрабатывается, и пользователь видит «Ошибка: Failed to fetch». Стоит обернуть вызов в `try/catch` и выдавать русский текст вроде «Нет связи с сервером. Повторите запрос.».
3. **Английские тексты в ответах 422.** Ошибки `ValueError` из `rating.py` («Cannot confirm empty field…», «Card exceeds 30000 characters») доходят до UI как есть (`main.py:210`). На практике это почти недостижимо: мешают клиентские проверки. Исключение — редкие Unicode-пробелы: JS `trim()` и Python `strip()` обрабатывают их по-разному.
4. **Мелочи UX.**
   - После save/confirm кнопки создаются заново, и фокус клавиатуры теряется.
   - Если в «Подтвердить отмеченные» после сохранения не осталось подходящих полей, правки уже сохранены, но показывается ошибка «Отметьте хотя бы одно…» (`:216`). Звучит так, будто ничего не произошло.
   - На textarea нет `maxlength`. Текст длиннее 20000 символов даст общее «Проверьте заполнение обязательных полей».
